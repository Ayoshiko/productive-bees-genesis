### 10.52 M06a 控制器粗状态与静态后备（2026-09-25，本步已验收）

**合同与接入：** 新增 `MachineVisualState` 和控制器专用 `status` 方块状态，映射未形成／检查中／结构就绪／等待区块／异常五类结构事实；普通部件不增加五态组合。状态仅在改变时连同 `formed` 投影给客户端，新观察者直接使用区块包中的状态。保留 `UPDATE_CLIENTS | UPDATE_KNOWN_SHAPE`，不会因纯展示更新查询邻居形状而加载缺失区块；没有额外 ticker、状态包、每帧世界扫描或视觉实例缓存。异常身份解除后，仍在场的同身份控制器立即同步并回到正式检查队列，避免显示长期停在故障。READY 只表示结构就绪，生产仍未开放。

**静态资源与参考：** 控制器用灰色空框、黄色横条、绿色勾形、蓝色暂停、红色交叉标志表达五态，颜色与形状共同区分；标志面固定亮度但方块世界发光值仍为零。观察窗使用透明玻璃渲染层，十一种角色方块加入现有创造页，控制器增加中英原型提示。读取 Neo ECO AE 当前 `645b8b1` 的 `NEBlockEntity.updateState/getUpdateTag` 与 `crafting_monitor_working.json`，采用变化才发布／新观察者完整状态及面级指示灯的原则；本项目没有其 AE2／LDLib 初始数据桥，粗状态由原版区块协议承载，更新 flag 也不能照搬。面级 `neoforge_data` 同时核对 NeoForge 21.1.214 的 `BlockElementFace/ExtraFaceData/QuadTransformers`，不使用已拒绝的旧 `forge_data` 字段。

**真实客户端证据：** `build/network-probe-m06a-client-lit-zh[-ae2]-20260925/results/machine-client.json` 两组均通过且正常保存退出。客户端从真实区块更新读取状态，覆盖四朝向、新跟踪状态、实际拆除／慢检查／重建、重复身份故障与恢复、十一种创造物品、40 个方块状态组合的模型／纹理／标志方向、面级光照和资源重载；每组九张截图已保存在同一 results 目录。原型材质在实拍中能区分状态并透过观察窗；前部接口对内部场景的遮挡须在 [9.2](bee-processing-network-visual-design.md#s9-2) 的锚点设计解决，不把占位材质称为最终美术。

**专服与构建证据：** `build/network-probe-m06a-formation[-ae2]-20260925/results/multiblock.json` 和 `build/network-probe-m06a-lifecycle[-ae2]-20260925/results/multiblock.json` 四组均通过并正常保存停服。前者复验三尺寸四向、500 tick 原绑定审计稳定性及拆除／冲突；后者额外断言 `waitingStateProjectedWithoutChunkLoad`，覆盖两轮 FULL 可用性降级、整台实际卸载、重复身份恢复和清理。每 tick STRUCTURES 工作数上限仍为 32，形成场景最慢单步约 13.8／19.6 ms，说明软时间预算不保证单次调用时限，不作 MSPT 改善结论。最终 test／build／verifyReleaseArtifact 通过，947 项测试中 945 通过、2 项既有跳过；JAR 3,419,259 字节，开发探针未打包。日志保留既有可选集成／ME／EME 配方和模型背景错误，目标门通过不表示整包日志无错误。本步不改存档格式，正常跨 JVM 恢复沿用 M03c，本轮未重跑 writer／reader。

**首次启动修复：** 每轮隔离目录原先缺少 `options.txt`，Minecraft 默认开启首次语言／辅助功能引导，使客户端探针需要人工点确认。共享 `prepareNetworkDomainProbe` 现在为新目录写入 `lang:zh_cn` 与 `onboardAccessibility:false`；两个客户端探针入口共用该准备任务。M06a 两组从首次启动直接进入测试，断言语言管理器确实选择简体中文且没有出现引导，退出后再次检查设置已保存。现有常规 run 目录原本已有相同设置，未覆盖其其它个人选项。专用服务器忽略客户端选项；该修复不是给服务器添加语言界面。

**剩余门：** 当前只交付基础状态与静态后备。WAITING 的真实缺区块投影由专服生命周期门验证，客户端只检查该状态模型，尚未从近处玩家制造真实缺区块并观察 WAITING 往返；不把这一分层证据写成五态均已完成客户端事件测试。内部场景、晚加入／离开视距／卸载重进的瞬态状态、动画、连接材质、光影、更多图形模式及多台帧耗仍在 M06b／c。[9.2](bee-processing-network-visual-design.md#s9-2) 的复杂演出只是设计合同；M04／P3 也没有随本步完成。

### 10.53 M06b1 有版本结构展示帧（2026-09-25，本步已验收）

**合同与实现：** `MachineVisualSnapshot` 只含 schema／布局版本、服务器会话发布号、机器身份／代际、固定模板索引、朝向及结构状态。严格字段与类型校验，完整 NBT 不超过 256 字节；没有所有者、库存、工作事件、任意组件或几何。`getUpdateTag/getUpdatePacket` 走原版区块追踪，初始帧完整、变化才发布；500 tick 重复状态发布保持字节和版本不变。同服务器所有维度共享发布号，控制器替换后旧身份帧也不能覆盖新帧；计数耗尽只停扩展展示，不回绕。

**权威隔离与失效：** 同时覆盖 NeoForge 的初始 `handleUpdateTag` 与增量 `onDataPacket`，只写单 BE 的展示收件槽，不能调用权威 `loadAdditional`；不保存视觉 revision，也没有全局客户端世界缓存。旧／重复版本拒绝，非法帧清空画面并保留版本水位；方向、状态或形成位不符时隐藏。客户端区块可在视距中心变化后暂留缓存而尚未 `setRemoved`，因此展示读取还须查询 `getChunk(FULL,false)` 并核对当前 BE；卸载／移除回调清理。返回后使用新的 BE 和完整初始帧。

**参考与失败修复：** 核对 Neo ECO AE `645b8b1` 的 `NEBlockEntity.updateState/getUpdateTag`，采用变化发布和完整初始状态原则；未引入 AE2／LDLib 权威数据桥。核对 NeoForge 21.1.214 的 `IBlockEntityExtension` 默认读取、原版 BE 数据包以及 `ClientLevel/ClientChunkCache/LevelChunk` 的卸载路径。首次自动卸载探针误用恒返回 true 的客户端 `hasChunk()`，导致等到总超时；改为实际缓存查询后又发现视距移出先于移除回调，已补展示有效性检查。失败轮保留在 `m06b1-client-final-20260925`／`m06b1-client-cachefix-20260925`，不计通过。探针增加阶段日志、普通阶段 45 秒及启动阶段 90 秒超时，失败也保存报告并正常退出；此前人工查看轮不作自动验证证据。

**验证：** 两组真实客户端 `build/network-probe-m06b1-tracking-20260925` 与 `m06b1-ae2-20260925` 均完成 step 10、正常保存退出，覆盖三布局、四方向、无权威客户端数据、重建后拒绝旧帧、资源重载和卸载重跟踪；各保留十张截图。专服 `m06b1-form[-ae2]-20260925`／`m06b1-life[-ae2]-20260925` 四组通过，形成门额外覆盖十二结构 500 tick 展示帧稳定性。全量 test／build／verifyReleaseArtifact 通过，952 项中 950 通过、2 项既有跳过；探针不进入产物。日志仍有既有 ME／EME 背景错误，本步不是整包零错误或性能验收。

**剩余门：** 本步只开放固定结构帧。内部静态场景／BER 继续 b2，纯时间轴与活动生命周期继续 b3；工作事件流的每查看者预算、M04 真实完成事件及 M06c 演出仍未实现。父阶段 M06b／M06 与 P3 不随本步关闭。

### 10.54 M06b2 内部静态场景与有限 BER（2026-09-25，本步已验收）

**实现与空间：** `CombinedApiaryScene` 为三种固定深度提供不可变蜂箱／蜜脾／箱子锚点；位于蜂箱单元上方、核心上方和离心单元上方，分别缩放为 0.8／0.65／0.8。与扫描共用 M01 连续坐标变换和模板视觉盒，所有模型范围位于预留空气格，不改变布局 1 的结构合同。`CombinedApiaryRenderer` 仅绘制有效 READY 展示帧；不创建蜜蜂／物品实体、临时方块或箱子 BE，也不读写库存。普通 BER 距离与视锥剔除保留，失效时只返回控制器本格范围；没有无限盒、强制 flush 或逐机可变姿态缓存。

**本地参考与资源：** 复核 AE2LT `1d4589b6` 的 `TianshuCoreEffectRenderer`，采用渲染和有限盒共用局部锚点的原则；本步是静态场景，不复制其弱引用动画表。对照 NeoForge 21.1.214 原版 `ChestRenderer`、`BlockRenderDispatcher` 和 `BlockEntityRenderDispatcher.onResourceManagerReload`：蜂箱／蜜脾引用原版方块模型，箱子直接烘焙 `ModelLayers.CHEST`，资源重载由原版重建 BER 和模型。注册类仅 `Dist.CLIENT` 加载，无新增 AE2／LDLib／Veil 必需依赖。

**实拍修正：** 首轮 `m06b2-scene-20260925` 的几何门通过，但实拍模型偏暗，原因是沿用不透明控制器所在格的光照。现改为从各模型空气格读取 BLOCK／SKY 光照缓存；不强制加载区块、不增加世界光源、不把模型全亮当作照明修复。探针以零控制器光照调用渲染，要求仍获得场景光照。`m06b2-lit-ae2-20260925`、`m06b2-lightwait-20260925` 与 `m06b2-lightdiag-20260925` 暴露首次搭建／传送期间的光照基线问题：服务器同点天空光照为 12、客户端可长期为 0，仅等待不能恢复。夹具改为先在远处等待至少 120 tick、服务器照明队列空且所有结构形成，再进入观察区，客户端另等各锚点日照就绪；仍以实际模型顶点光照检验取样，不注入客户端光照。失败轮均正常退出并保留，未计入通过。观察夹具将原有允许玻璃的第 3 层外壳换成玻璃；这只是合法搭建选择，没有放宽模板。正面接口和不透明框架仍真实遮挡场景，部分斜视角只能看到部分模型。

**验证：** `build/network-probe-m06b2-settled[-ae2]-20260925/results/machine-client.json` 两组完成 step 11 并正常保存退出，各保留十四张截图；核对四正视／四斜视及失效画面。真实模型顶点逐点落在对应空气锚点及有限盒中，三个道具都有实际几何；未形成／故障时零顶点；资源重载重新取得 BER，离开视距再返回恢复完整场景。专服 `m06b2-server[-ae2]-20260925` 两组形成回归与停服通过，验证客户端类没有进入专服加载入口。新增 2 项纯几何测试，全量 test／build／verifyReleaseArtifact 通过：954 项中 952 通过、2 项既有跳过。探针未打包；M06b1 卸载专服矩阵本步未重复。

**剩余门：** 原版资源在 Fancy 设置下通过，不代表任意资源包扩大的模型、Fast／Fabulous、Iris 或多台帧耗均已验收。此处只展示静态装置，不循环伪造生产；飞入、放大／淡出、压榨液流、资源爆发／悬浮／收纳仍待 b3／M06c，M04 真实工作触发和活动流总预算仍是独立进入门。

### 10.56 M06b3b 活动接收、取消与客户端生命周期（2026-09-25，本步已验收）

**合同与接入：** `MachineActivityInbox` 由单个控制器持有，不包含世界引用或模型；按完整结构帧身份／版本匹配，首次基线不回放，单调事件序号拒绝重复。未来时间、超出对应片段窗口、距离或总活动数量拒绝也消费序号；单机只保留当前和最新后继。取消保持基线，结构失效保持结构发布水位，较新的 READY 帧重新建立事件基线。先做 long 时间差再加 partial tick，避免长期世界丢失小数精度。未形成帧同样推进版本水位；自然结束后的长时间空闲不触发活动跳时保护，二者均在审查中补了回归测试。
